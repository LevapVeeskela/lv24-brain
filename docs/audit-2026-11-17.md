## Ответы на вопросы

**Граф по проектам.** Native-граф работает и по умолчанию изолирован:
`index/graph/<project>-<sha8(root)>.db`. Но: (1) глобальный `codegraph` ломает
`brain code status` там, где нет `.codegraph`; (2) `brain open` не показывает native-индекс;
(3) устаревание не вычисляется (статус врёт); (4) identity БД можно подменить `--db`;
(5) аналитика доступна только через MCP.

**Импорт из RAG.** engram — работает, но с потерями: нет per-note updated_at, prompts,
части relations; повторный импорт не атомарен и воскрешает trash. Exchange не
идемпотентен и теряет path_provenance/pins. mem0/letta/zep не поддерживаются.
Коннекторные данные — raw items, не курируемые записи, и сейчас не поступают.

**Хуки.** Реально работают: Codex (trusted), OpenCode (loaded), git post-commit.
Claude Code — не установлены. Ни один хост не сообщает о сбое; автоматических
handoff нет. OpenCode не собирает `Decision:`.

**Мульти-сессии.** Каркас крепкий: per-file locks, atomic rename, cross-process тесты,
3-machine сценарий. Риски: consolidate/sync против живых писателей, stash drop,
потеря frontmatter при merge, журнал без cross-process lock.

**Мульти-проектность.** Работает при явном scope. По умолчанию journal, prompts и
нескоупленный search видят все проекты. Alias/path коллизии не валидируются.
Multi-project коннекторы теряют привязку к проекту.

### Критерии «полноценного second brain»
1. Retrieval: на 30 реальных запросах релевантная запись в top-5 ≥ 80%; контекст
   содержит решение/попытку по задаче, а не брендинг.
2. Мульти-сессии: 3 машины × 2 сессии без потерь; consolidate во время записи безопасен.
3. Мульти-проект: ни одна дефолтная поверхность не течёт между проектами; alias/path
   уникальны; connector items привязаны к проекту.
4. Импорт: round-trip идемпотентен, 0 потерь, prompts/relations учтены.
5. Хуки: все три хоста показывают installed/trusted/last-run; ≥1 auto handoff за сессию.
6. Производительность: context < 1 c на 1.7k записей/проект; pull-reindex < 4 c;
   индекс без 100+ МБ WAL.
